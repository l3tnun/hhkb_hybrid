# 純正 FW の電源管理 (電源ボタン・スリープ) 解析

- 作成: 2026-09-13 (静的解析)
- 対象: 純正 A0.48 STM32 アプリ (`hhkb_stock_128k.bin` 0x08010000〜)。静的解析のみ
- 中間生成物: `build/b4/power/` (Git 管理外)
- [C] = コードで確認、[I] = 推定

## 1. 全体像

- ラッチ/レギュレータ制御ピンは無い [I 高]。「電源オフ」と「無操作スリープ」は同じ状態 (状態 0)
- 状態 0 では nRF を待機 (`40` → 03 に `10 00`、`83 01` を最大 3 秒待つ) にし、マトリクス/アナログ出力を Low にして、MCU を **STOP** (PWR_CR LPSDSR=1, PDDS=0, SLEEPDEEP, WFI;) [C]
- 起床要因は **EXTI5 (PC5 = 電源ボタン)** と **EXTI13 (PC13 = USB 給電)** の**立ち下がりのみ** (HAL mode 0x10210000) [C]。キーでは起きない。RTC/LPTIM/IWDG は使っていない [C]
- USB 給電中は STOP に入らない (ビジーループで SPI を処理)、USB サスペンドでも寝ない [C]

## 2. 電源ボタン (PC5)

| 状況 | 操作 | 動作 | 根拠 |
|---|---|---|---|
| 動作中 | 短押し (0.1〜2 秒) | 状態 3 (接続中) なら接続スロット番号の回数 LED0 点滅 [I]、状態 5 なら再接続 |〜 [C] |
| 動作中 | 2 秒長押し | 状態 0 (オフ)。USB 給電中も同じ | ほか [C] |
| オフ (STOP) | 1 秒以上押して 10 秒未満で離す | 起床: PC14 High、電池チェック、LED0 消灯、BT 再接続 (状態 4) または USB (0x3C) | [C] |
| オフ | 1 秒未満 | STOP に戻る | [C] |
| オフ | 10 秒以上 | LED1 を 3 秒点灯して、オフのまま | [C] |

オフへの手順: LED0 消灯/LED1 点灯 → nRF 待機 → (電池時) USB 停止 (USB_CNTR=0, D+ プルアップ解除) → `83 01` 待ち (3 秒) → LED1 消灯 → ボタンを離すまで待つ → PB0〜2, PB10〜15, PC6, PC7, PC8, PC14 を Low → STOP ループ。

起床時: PC13 でクロック選択 (電池 4MHz / USB 16MHz + HSI48・CRS。§7-1) → ADC・タイマー・SPI1・NVIC (SPI1, EXTI4_15)・USB (USB 給電時のみ) を再初期化。

## 3. 無操作スリープ

- カウンタ `0x2000009C` (秒)。状態 3/5 で、VBUS 無し かつ DIP SW6 相当 (`0x20000086[5]` = PC4 Low) が OFF のときだけ進む。キー押下でリセット [C]
- 上限 = `0x20000079` × 60 秒 → 状態 0。設定値は **EEPROM `0x08080520`** (1〜60 分、0 または 60 超なら 30 を保存) [C]
- その他のタイムアウト: ペアリング待ち 600 秒、状態 2 600 秒、再接続 60 秒 → 状態 0 (VBUS/SW6 なら状態 5) [C]
- DIP SW6 (PC4) ON: STOP せず状態 5 でキー走査を続け、キーで再接続 [C]。SW6 = 「キーで起床」[I 中高]
- QMK は再接続 60 秒の打ち切りと、SW6 ON 時の状態 5 相当（nRF 待機・LED 消灯・キー/電源短押しで再試行）を実装する。全スロット未登録時の自動 `01 00` は真似しない。仕様は [../usage.md](../usage.md)

## 4. 電池残量低下

- PB9 Low (0%) で電池時 LED1 点灯。2 秒長押しまたは 180 秒で: nRF 待機・出力オフ → **EXTI5 を無効化** (ボタンでは起きない) → STOP → USB 挿入でのみ起床 → リセット [C]

## 5. USB 給電の抜き差し

- STOP 中の USB 挿入: PC13 で起床、状態 0x3C (USB) [C]
- 動作中の抜去: 状態 3/5 (USB クロック) ならシステムリセット、0x3D なら状態 0。STOP 中の抜去では起きない [C]

## 6. QMK での注意点 (推定)

- **IWDG**: QMK は起動直後に IWDG (約 7 秒) を開始しており、STM32L0 の IWDG は STOP 中も止まらない。期限切れのリセットは `__early_init` のフェイルセーフで**更新モード**に入る → STOP 中も LSI 起動の LPTIM1 (EXTI29) で約 2 秒ごとに起きて IWDG を更新する必要がある
- `stm32_clock_init()` は RCC APB1ENR / PWR_CR / CCIPR / SYSCFG_CFGR3 を上書きする → STOP から復帰して再開するより、**起床 = ソフトウェアリセット**が単純 (純正のリセット経路と同様)。代償: ブートローダーが PD2 を High にするので nRF がリセットされ、再接続まで約 10 秒
- STOP 中は TIM21 (ChibiOS の時刻) が止まる。EXTI の保留 (ボタンのバウンス) はクリアしてから入る
- リーク対策: PC14/PC7/PC8 を Low、PB6 は High、USB の D+ プルアップと HSI48/VREFINT を止める
- STOP 中は SPI に応答できない → 事前に nRF を待機にする (応答の無い問い合わせを nRF が最大 600 回再試行するため)
- スリープ状態は保持しない (電源の入れ直し = 通常起動) ので、電池の抜き差しで必ず復帰できる

## 7. 電池駆動中（接続中）の電力 と QMK の省電力動作

- 静的解析: 2026-09-29。対象は §1 と同じ純正 A0.48 アプリ。アドレスは flash 上の値
- QMK の実装: `keyboards/hhkb_hybrid/power.c`（`HHKB_LOW_POWER`）、`matrix.c`。利用者向けの説明は [../usage.md](../usage.md#電池駆動時の省電力動作)

### 7-1. 純正のクロック [C]

起動時（`0x0801C454`）と STOP からの起床時（`0x08011AC6`）に PC13 を読み、クロックを選ぶ。

| | 電池（PC13 High）`0x08015CF4` | USB 給電（PC13 Low）`0x08015C1C` |
|---|---|---|
| SYSCLK | HSI16 ÷4（HSIDIV）→ PLL ×4 ÷4 = **4 MHz** | **HSI16 直結 = 16 MHz** |
| 電圧レンジ（PWR_CR VOS） | Range 1 | Range 1 |
| HSI48 / CRS | 触れない | HSI48 を USB に使い、CRS を USB SOF に同期 |
| TIM21（1 ms 刻み） | PSC 99、ARR 40（約 1.03 ms） | PSC 99、ARR 160（約 1.01 ms） |
| USB の初期化 | しない（`0x0801C570` 以降の電池用初期化に USB が無い） | する（`0x08015360`） |

フラグ `0x20000045` = 1 が電池用クロック。§2 の「電池 4MHz」はこの表のとおり。

### 7-2. 純正のメインループとキー走査 [C]

- **WFI を使うのは STOP に入る関数（`0x08012D84`）だけ**。電池駆動で接続中（状態 3）も、CPU は 4 MHz で動き続ける（Sleep モードは使わない）。
- TIM21 の割り込み（`0x08013F7C`）が 1 ms ごとにカウンタを増やす。メインループから呼ばれる `0x08014EA4` が、この刻みを**電池時 11 回、USB 時 16 回**数えるごとに全キー走査を始める（電池時は約 11 ms ごと）。
- 全キー走査は 1 キーずつ（`0x08014C94`、キー番号 = 列 × 8 + 行、無効な番号は表 `0x0801DB68` で飛ばす）。1 キーの手順：
  1. `0x0801C5F4`：**C7（OpAmp）を High**、C6/B15 で U1/U2 を選び、列を選ぶ。列の先頭では短く待つ（電池時は空ループ 1 回）。C8（放電）を High にして短く待つ。
  2. `0x0801C2AC`：空ループ 15 回 → C8 を Low → 行（B0/B1/B2/B10/B11）を High → 対象の行を Low → 待つ（電池時は空ループ 3 回、USB 時は 35 回）→ ADC で 1 回変換 → 行を High に戻す。
  3. 押下を検出したら、約 1 ms（電池時は空ループ 250 回 × 3）待って読み直して確定する。
  4. **C7（OpAmp）を Low**（`0x08014E16`）。
- C7 は 1 キーごとに ON/OFF する。
- **C14（スイッチ基板の電源）は、`0x08014EA4` が毎回 High にしており、常に ON**。
- ADC は起動時に一度有効（ADEN）にして、そのまま使い続ける（`0x08019550`）。設定はクロック同期（PCLK ÷1）、12 ビット、サンプリング 1.5 サイクル（`0x08015058`）。電池時は 4 MHz で変換する。

### 7-3. SPI・PB6・電池残量通知

- PB6 の要求パルスは、純正はキーの変化ごと（[bluetooth-protocol.md](bluetooth-protocol.md) §5）。QMK はキーレポートごとに 1 回で、再送は 30 ms 間隔で最大 5 回。今回は変えていない。
- QMK は電池残量を、接続時と変化したとき（3 回連続で同じ値のとき）にだけ送る。純正の送信頻度は未確認。

### 7-4. QMK の省電力動作（`HHKB_LOW_POWER`、既定で有効）

変更前の QMK は、電池駆動中も 32 MHz（PLL、Range 1）で、待ちを入れずに全キー走査を繰り返していた。OpAmp（C7）は走査の終わりにだけ OFF にし、ADC は常に有効で、USB も起動したままだった。

| 項目 | 変更前 | 変更後（電池駆動中のみ） | 根拠 |
|---|---|---|---|
| クロック | PLL 32 MHz | HSI16 ÷4 = 4 MHz。PLL・MSI・HSI48・CRS を停止。Flash の待ちと先読みを無効 | 純正と同じ 4 MHz（7-1） |
| 走査の頻度 | 待ちなしで連続 | 5 ms ごと（`HHKB_LP_SCAN_INTERVAL_MS`）。残りの時間は ChibiOS の idle スレッドで WFI（Sleep） | 純正は約 11 ms ごと（7-2） |
| OpAmp（C7） | 走査の終わりにだけ OFF（走査が連続） | 走査中だけ ON。ON にしてから 30 µs 待つ | 純正は 1 キーごとに ON/OFF（7-2） |
| ADC | 常に有効 | 走査の前に ADEN、後に ADDIS。変換時の設定（4 MHz、1.5 サイクル）は純正と同じ | 純正は常に有効（7-2）。走査の間は使わないので止める |
| USB | 起動したまま | 停止（`usbDisconnectBus()` と `usbStop()`） | 純正は電池時に USB を初期化しない（7-1） |
| C14 | 常に ON | 変えない | 純正も常に ON |

- 切り替えは `power_task()` が行う。PC13 が 50 ms 安定してから切り替え、起動後 1 秒間は切り替えない（QMK は `keyboard_pre_init` の後に USB を起動するので、起動直後に下げると PLL 無しで USB を起動してしまう）。USB 給電を検出したら 32 MHz に戻し、`restart_usb_driver()` で USB を起動し直す。
- ChibiOS はビルド時のクロック（32 MHz）から TIM21（システムティック、1 kHz）と TIM3（`wait_us`、1 MHz）の分周を計算する。切り替えのたびに TIM21 の PSC を書き直し（CNT は保存して戻す）、GPT ドライバの `GPTD3.clock` を書き換える。
- 4 MHz では `wait_us()`（呼ぶたびに TIM3 を起動し直す）が重いので、マトリクスの短い待ちは 1 回 3 サイクル以上の空ループにした（要求時間より短くならない）。USB 給電中は従来どおり `wait_us()`。
- `wait_us(1)` は使わない。ChibiOS の `gptPolledDelay()` は ARR = 間隔 − 1 = 0 を設定し、ARR が 0 の間タイマーは止まるので、戻ってこない（試作でこれを起動時に呼び、IWDG のフェイルセーフで更新モードに落ちた）。
- 4 MHz での nRF との SPI（nRF は 125 kHz のマスタ）は、実機の電池駆動で Bluetooth の入力とスロット切替ができることを確認した。
- 見送ったもの：
  - 未使用ピンのアナログ入力化：どのピンが未使用かを確認していないため。
  - 電圧レンジを下げる（Range 2/3）：純正も Range 1 のまま（7-1）。
  - Sleep 中の Flash 停止（FLASH_ACR SLEEP_PD）：実機で確認していないため。
  - ADC の auto-off（CFGR1 AUTOFF）：変換ごとに ADC の起動時間が入り、行を駆動してから変換するまでの時間が純正と変わるため。
- `HHKB_LOW_POWER=no` のビルドは、省電力動作を入れる前のファームとバイト単位で同じ。
